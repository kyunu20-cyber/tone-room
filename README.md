# EVA-95 VIDEO PROCESSOR

실사 여행 영상에 1995년 일본 TV 애니메이션 방송 마스터의 색감과 필름 질감을 입히는 로컬 보정 앱입니다.

**보정만 합니다.** 영상을 애니메이션 그림처럼 바꾸지 않습니다. 색 수를 줄이거나, 페인팅처럼 뭉개거나, 외곽선을 그리거나, 얼굴을 바꾸는 처리는 없습니다. 색·톤·필름 질감만 다룹니다.

모든 처리는 이 Mac 안에서 이뤄집니다. 영상을 외부로 보내지 않고, 유료 API나 로그인도 필요 없습니다.

## 설치

1. [Releases](../../releases)에서 `TONE-ROOM-x.y.z-arm64.dmg`를 받습니다.
2. dmg를 열고 TONE ROOM을 응용 프로그램 폴더로 끌어다 놓습니다.
3. 처음 열 때 “확인되지 않은 개발자” 경고가 뜨면, TONE ROOM을 **우클릭 → 열기**를 누릅니다. 애플 개발자 서명을 하지 않은 앱이라 한 번만 거치는 단계입니다.

**Apple Silicon(M1 이후) 맥과 macOS 14(Sonoma) 이상이 필요합니다. Intel 맥은 지원하지 않습니다.** Python·Node·FFmpeg는 앱 안에 들어 있어서 따로 설치할 것이 없습니다.

- 앱은 내부 서버를 127.0.0.1의 빈 포트에 띄우고 자체 창에 화면을 엽니다. 브라우저가 필요 없습니다.
- 업로드·캐시·사용자 프리셋: `~/Library/Application Support/TONE ROOM/`
- 출력 폴더 기본값: `~/Movies/EVA95/`
- AI 업스케일(애플 초해상도)은 macOS 26 이상에서만 나타납니다.

## 소스에서 실행(개발)

필요한 것: macOS(Apple Silicon 권장), [Homebrew](https://brew.sh)

```bash
brew install ffmpeg node python@3.11   # 이미 있으면 생략
./start.sh
```

처음 실행하면 Python 가상환경(`backend/.venv`)과 npm 패키지 설치, 프론트엔드 빌드까지 자동으로 진행합니다. 몇 분 걸립니다. 준비가 끝나면 브라우저에서 http://localhost:3095 이 열립니다.

항상 켜 두려면 macOS 로그인 항목(LaunchAgent)으로 등록합니다. 로그인할 때 자동으로 켜지고, 프로세스가 죽으면 launchd가 다시 띄웁니다.

```bash
./scripts/install-service.sh     # 등록 (로그: ~/Library/Logs/EVA95/eva95.log)
./scripts/uninstall-service.sh   # 해제
```

- 프론트엔드와 백엔드는 모두 127.0.0.1에만 바인딩됩니다. 같은 네트워크의 다른 기기에서는 접속할 수 없습니다.
- 백엔드: http://127.0.0.1:8095 (FastAPI)
- 출력 폴더 기본값: `~/Movies/EVA95/`
- 프론트엔드 코드나 사용설명서를 고치면 다음 실행 때 자동으로 다시 빌드합니다. 강제로 다시 빌드하려면 `EVA95_REBUILD=1 ./start.sh`.

## 사용 방법

1. `[ DROP VIDEO HERE ]`에 영상을 끌어다 놓습니다(MP4·MOV·MKV·WEBM, 여러 개 가능).
2. 프리셋을 고릅니다. 기본값은 **IPHONE 17 NATURAL**입니다.
3. 원본과 처리본을 나란히 보거나(SPLIT), 비교 슬라이더(COMPARE)로 봅니다. 프레임 단위 이동, 줌, 전체화면, 끝까지 이어지는 동기 재생(구간 단위로 보정하며 다음 구간을 미리 만듦)을 지원합니다. 설정은 클립마다 따로 저장되고 UNDO/REDO로 되돌릴 수 있습니다.
4. 슬라이더로 조정합니다. 미리보기는 150ms 뒤에 자동으로 갱신됩니다.
5. 해상도·프레임레이트·코덱·품질을 고르고 내보냅니다. 여러 클립을 한꺼번에 내보낼 수도 있습니다. 파일 이름은 `원본이름_EVA95.mp4`가 됩니다.

## 프리셋

| 프리셋 | 특징 |
|---|---|
| IPHONE 17 NATURAL (기본) | 깨끗한 폰 감성. 하이라이트 여유, 살짝 뜬 검정, 중간 대비, 중립 WB, 화사한 피부. 폰·밝은 조명 영상용 |
| IPHONE 17 VIVID | 같은 방향에서 색과 대비를 한 단계 더. 야외·풍경용 |
| IPHONE 17 SOFT | 더 부드럽고 따뜻하게, 자글거림을 강하게 정리. 웹캠(포토부스)·저조도 영상용 |
| EVA-95 ORIGINAL TV | 깊은 검정, 푸른 암부, 크림빛 하이라이트(스플릿 토닝), 고운 필름 입자, 텔레시네의 부드러움, 절제된 블룸 |
| EVA-95 CEL COLOR | 셀 물감 특유의 색 경향(하늘은 청록 쪽, 녹색은 올리브 쪽, 빨강은 깊게)을 가장 강하게. 형태와 디테일은 그대로 |
| EVA-95 CINEMATIC | 같은 색 방향을 한 단계 약하게. 입자 적고 디테일 보존. 인물 브이로그용 |
| EVA-95 ARCHIVAL | 바랜 색, 뜬 검정, 굵은 그레인, 약한 흔들림, 부드러운 하이라이트 확산 |

`LOOK INTENSITY`(MASTER, 0~1.5)는 모든 "효과량" 파라미터를 중립값 기준으로 함께 늘리거나 줄입니다. 임계값, 반경, 주파수, 피부 보호 같은 설정값에는 곱하지 않습니다(`params.effective`).

원래 요구서에는 CEL BACKGROUND 프리셋(색 단순화와 페인팅 스무딩)이 있었습니다. "화풍은 바꾸지 않는다"는 원칙에 따라 CEL COLOR(색 반응만 강화)로 대체했습니다.

프리셋 값은 `backend/eva95/presets/*.json`에 고정돼 있어서 같은 입력이면 항상 같은 결과가 나옵니다. 모든 파라미터의 범위와 중립값은 `backend/eva95/params.py` 한 곳에서 정의합니다. 사용자 프리셋은 `data/presets/user/`에 저장됩니다.

IPHONE 17 프리셋은 실제 레퍼런스 영상 5개(밝은 실내 셀프캠)를 측정한 값(`data/iphone_ref_stats.json`)을 목표로 잡았습니다. IPHONE LOOK 그룹의 네 파라미터를 씁니다.
- **HDR tone mapping**: 주변 밝기 기준 국소 톤매핑. 암부는 올리고 명부는 누르며 중간톤은 거의 그대로
- **Vibrance**: 채도 낮은 색만 올림, 피부는 보호
- **Noise reduction**: 휘도는 윤곽 보존 필터, 색 노이즈는 크로마만 블러. 웹캠 자글거림 완화
- **Detail**: 윤곽 위주 선명도. 노이즈 많은 영상에서 올리면 자글거림도 커짐
- **Yellow cast removal**: 전구 조명 누런기 제거. 중간톤·명부를 중립 쪽으로, 노랗게 뜬 피부는 혈색 쪽으로

## 업스케일

출력이 원본보다 클 때 내보내기의 UPSCALE 방식이 적용됩니다.
- **STANDARD**: lanczos 확대
- **SHARP** (기본): lanczos 확대 + ffmpeg `cas` 선명화
- **AI (APPLE)**: macOS 26 VideoToolbox 초해상도(`VTSuperResolutionScaler`, 4배). 1/4 크기에서 보정한 뒤 `tools/vtsr`로 4배 키웁니다. `start.sh`가 `swiftc`로 빌드하며, 모델이 출력 밝기를 약 3.5% 낮추는 것을 역LUT로 보정합니다. M5 Pro에서 540p→4K 기준 프레임당 약 0.2초

## 처리 파이프라인

프레임마다 아래 순서로 처리합니다. 난수는 `(seed, 프레임 번호)`로 고정되므로 미리보기와 최종 렌더 결과가 같습니다.

1. **샷 매칭**: 클립 단위 고정 노출·화이트밸런스·대비 보정(아래 절)
2. **색 반응**: 감마, 암부 토 압축, 하이라이트 숄더 롤오프, 필름 S-커브 대비, 스플릿 토닝(암부 청록·명부 따뜻하게), 색온도·틴트. 모두 채널별 256단계 LUT 하나로 합쳐 빠르게 적용합니다.
3. **채도·셀 색 경향**: HSV에서 색상별로 미세 보정합니다. 피부 영역(YCrCb 마스크)은 변화를 억제합니다.
4. **광학적 부드러움**: 작은 반경 블러를 엣지 마스크로 조절해 윤곽과 얼굴선은 유지하고 미세 디테일만 약하게 합니다. 할레이션은 선택 사항입니다.
5. **하이라이트 블룸**: 임계값 이상만 추출해 넓게 퍼뜨리고, 스크린 합성 상한을 둬서 화면을 덮지 않게 합니다.
6. **색 어긋남**: R/B 채널을 서브픽셀만큼 어긋나게 하고 경계 부근에서만 보이게 합니다. 기본값은 약 0.13px입니다.
7. **필름 에이징**: 블랙 리프트, 페이드, 따뜻한 쪽 이동(LUT에 포함)
8. **필름 그레인**: 블러한 노이즈로 입자 크기를 조절하고, 중간톤에서 가장 강하게 줍니다. 기본은 모노크롬이고 색 입자 비율과 인접 프레임 상관(시간적 일관성)을 조절할 수 있습니다.
9. **게이트 위브**: 여러 주파수 사인파를 합친 부드러운 x/y 서브픽셀 이동입니다. 기본값은 0.5px 미만입니다.
10. **케이던스**: 출력 FPS는 ffmpeg로 CFR 변환합니다. 12FPS 시뮬레이션은 24fps 컨테이너를 유지하고 2프레임마다 같은 프레임을 반복합니다.

## EVA-95 SHOT MATCHING

조명이 제각각인 클립들을 같은 톤으로 모으는 전처리 단계입니다. `AUTO SHOT MATCHING [ON/OFF]`로 끌 수 있습니다.

- **분석**: 첫 프레임을 포함한 대표 프레임 12장(짧은 변 360px)에서 노출(휘도 중앙값), 섀도·하이라이트 분포(p1, p99.5), 대비(휘도 표준편차), 채도, 화이트밸런스를 측정합니다. 화이트밸런스는 피부·클리핑·극단 휘도 픽셀을 뺀 무채색 위주 픽셀로 추정합니다.
- **보정**: 프리셋의 목표값(노출·대비·채도)을 기준으로 노출 게인, 채널별 WB 게인, 대비, 채도 배율을 계산합니다.
- **안전장치**
  - 하이라이트 보호: 노출을 올려도 p99.5가 0.97을 넘지 않습니다.
  - 흰색 보존: 노출을 내려도 p99.5가 0.88 아래로 내려가지 않습니다. 흰 벽이 회색으로 탁해지는 것을 막습니다.
  - 섀도 보호: 대비를 올려도 p1이 0 아래로 뭉개지지 않습니다.
  - 대비는 주로 올리는 쪽으로만 맞춥니다. 이미 대비가 강한 영상도 최대 8%까지만 낮춰서, 프리셋 효과가 샷 매칭에 상쇄되지 않게 합니다.
  - 피부 보호: WB 때문에 피부 색상이 4° 넘게 돌면 WB 강도를 줄입니다.
- **시간 안정성**: 클립당 보정값 하나를 모든 프레임에 똑같이 적용합니다. 프레임마다 다시 계산하지 않으므로 노출이 출렁이지 않습니다.

## 내보내기

- ffmpeg 디코드 → NumPy/OpenCV 보정 → ffmpeg 인코드를 파이프로 연결합니다. 중간 영상 파일을 만들지 않고, 영상 전체를 메모리에 올리지 않습니다.
- 원본 오디오는 AAC 320kbps로 넣습니다. 원본에 오디오가 있는데 출력에 없으면 실패로 처리합니다(조용히 버리지 않음).
- H.264/H.265는 Apple VideoToolbox 하드웨어 인코더를 먼저 쓰고, 안 되면 libx264/libx265로 자동 전환합니다. 디코드도 VideoToolbox 가속을 씁니다.
- CapCut 호환 규격: MP4, yuv420p, BT.709 태그, CFR, `faststart`, HEVC는 `hvc1` 태그
- 세로 영상(9:16 Reels)은 회전 메타데이터를 반영해 세로로 출력합니다. 1080p/4K는 짧은 변 기준이고 비율을 유지합니다.
- 아이폰 HDR(HLG/PQ, BT.2020) 영상은 SDR(BT.709)로 톤매핑합니다.
- 렌더는 임시 파일에 쓴 뒤 성공했을 때만 최종 위치로 옮깁니다. 취소하거나 실패하면 임시 파일을 지우고, 다음 실행 때도 남은 임시 파일을 정리합니다.

## 성능 (Apple M5 Pro, 48GB에서 실측)

아이폰 세로 4K HDR(HEVC 10bit HLG) 8.7초 클립, ORIGINAL TV 프리셋, H.264 VideoToolbox 기준입니다.

| 출력 | 처리 속도 | 최대 메모리 |
|---|---|---|
| 1080p | 초당 34~37프레임(실시간보다 빠름) | 약 1.7GB |
| 4K 원본 해상도 | 초당 6.3~6.5프레임 | 약 3.9~4.1GB |

- 33.6초 클립도 1080p에서 최대 메모리 1.7GB로, 영상 길이와 무관하게 일정했습니다.
- 4K는 메모리 예산(기본 3GB)에 맞춰 동시 처리 프레임 수를 줄입니다. 메모리가 넉넉하면 `EVA95_MEM_GB=6 ./start.sh`로 더 빠르게 돌릴 수 있습니다.
- GPU 사용 범위: 디코드와 인코드는 VideoToolbox(GPU/미디어 엔진)를 씁니다. 프레임 보정은 CPU(OpenCV NEON + 멀티스레드)로 처리합니다. OpenCL 경로도 검토했지만, 프레임 단위 병렬 CPU 처리로도 1080p에서 실시간보다 빨라서 복잡도를 늘리지 않았습니다.

## 테스트

```bash
cd backend && .venv/bin/python -m pytest -q
```

테스트용 영상은 ffmpeg로 그때그때 합성합니다(가로, 세로, 무음, 가변 프레임레이트, 한글 경로, 노출이 다른 두 클립, 잘린 파일, 쓰레기 데이터). 검증 항목은 다음과 같습니다.

- 중립값이면 원본과 동일, 결과의 결정성, 모든 프리셋에서 윤곽 구조 보존(화풍 불변)
- 그레인의 휘도 의존성, 위브가 미세하고 부드러운지, 블룸 상한, 피부 보호
- 샷 매칭: 노출이 다른 클립끼리 차이가 줄어드는지, 하이라이트·섀도·흰색·피부 보호, 프레임 간 보정이 일정한지
- 내보내기: 오디오 보존과 싱크, CFR, 세로 비율, 무음 입력, VFR→CFR, 한글 경로, 12FPS 시뮬레이션, H.265, 취소 시 정리, 손상 파일 거부
- API: 업로드, 미리보기, 프리셋 저장·삭제, 배치 3개 내보내기·취소·재시도, 실패 메시지, 미리보기 클립

- 샷 매칭은 클립 단위 고정값입니다. 한 클립 안에서 조명이 크게 바뀌면(실내→실외로 걸어 나가는 장면 등) 평균에 맞춰집니다. 이런 클립은 나눠서 넣는 편이 낫습니다.
- 극단적인 역광이나 아주 어두운 밤 영상은 보호 장치 때문에 일부만 맞춰집니다.
- HDR→SDR 톤매핑은 단순한 숄더 곡선이라 Apple 사진 앱의 SDR 변환과 똑같지는 않습니다.

## 앱 빌드

```bash
backend/.venv/bin/pip install -r backend/requirements.txt pyinstaller
packaging/build.sh        # dist/TONE ROOM.app 과 dist/TONE-ROOM-<버전>-arm64.dmg
```

프론트엔드는 정적 HTML(`frontend/.next-export`)로 빌드해 백엔드가 같이 서빙합니다. 버전은 `VERSION` 파일 하나에서 정합니다. `v`로 시작하는 태그를 올리면 GitHub Actions가 dmg를 만들어 Releases에 붙입니다(`.github/workflows/release.yml`).
